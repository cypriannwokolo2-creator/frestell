CI/CD Pipeline

# On every PR
ci.yml →
  - Install dependencies
  - Lint (eslint, prettier)
  - Type-check (tsc, rust clippy)
  - Test (Jest, vitest, cargo test)
  - Build (next build, nest build, cargo build)
  - Security scan (CodeQL)

# On merge to main
deploy-staging.yml →
  - Build Docker images (all services)
  - Push to staging registry
  - Deploy to staging environment
  - Run smoke tests

# Manual trigger for production
deploy-prod.yml →
  - (same build + push steps)
  - Manual approval gate
  - Deploy to prod
  - Health checks

Root package.json Scripts Example

{
  "scripts": {
    "dev": "nx run-many --target=serve --projects=web,api",
    "build": "nx run-many --target=build --projects=web,api",
    "test": "nx run-many --target=test",
    "lint": "nx run-many --target=lint",
    "format": "prettier --write .",
    "affected": "nx affected --targets=test,lint,build",
    "docker:build": "docker-compose build",
    "docker:up": "docker-compose up -d",
    "deploy:staging": "./infrastructure/scripts/deploy-staging.sh",
    "deploy:prod": "./infrastructure/scripts/deploy-prod.sh"
  }
}

Best Practices

  • Every commit must pass linting & tests (enforced by pre-commit hooks)
  • Use conventional commits (feat:, fix:, docs:, refactor:, test:, chore:)
  • PR must be approved before merge (CODEOWNERS enforcement)
  • Automated deployments to staging; manual approval for prod
  • Keep `.env.example` updated when adding new secrets/config
  • Document all setup steps in README.md and CONTRIBUTING.md
